# TDD 유닛 테스트 설계 (`TESTS.md`)

관련 문서: [계획 개요](README.md) · [UX·UI 설계](DESIGN_UI.md) · [데이터·네트워크·보안 설계](DESIGN_DATA.md) · [사용자 시나리오](SCENARIOS.md)

> **원칙**: TDD(실패 테스트 먼저 작성 → 구현 → 정리)는 아래 선정된 7개 크레이트 22개 유닛 테스트 그룹에만 적용한다. 각 경계는 정규 소유 크레이트에서 1회 집중 검증하며, 모든 `test-reviewer`(F-01..F-13) 및 `security-reviewer`(E-SEC-01..E-SEC-08) 수정 사항을 반영했다.
> **규범 명칭**: 전 테스트는 `AgentState::{ Idle, Working, Blocked, Done, Error }` 및 `BlockedKind::{ Permission, Question, Auth }`를 사용한다(구명칭 `"running"`, `"waiting"`, `"approval"`, `"input"`, `"turn"`은 음성 단언 거부 대상).
