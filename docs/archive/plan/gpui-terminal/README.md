## 조사 결과

제거한 웹 UI는 ghostty-web에 WASM VT, Canvas, 브라우저 키 이벤트를 맡긴다. 셀 높이·사선·스크롤바는 내부 동작을 보정 중이다. 당시 Rust PTY는 탭별 실행·입출력·리사이즈·종료를 담당한다. WebView 새로고침은 같은 셸에 최근 128 KiB를 재생하는 근사치이며, 앱 종료 후 재접속은 아니다.

[Herdr의 VT 코드](https://github.com/herdrdev/herdr-app/blob/b41b5cbf/src/vt.rs)와 [터미널 뷰](https://github.com/herdrdev/herdr-app/blob/b41b5cbf/src/terminal.rs)는 GPUI + 네이티브 libghostty-vt가 실제로 쓰이는 사례다. [Ghostty 1.x C ABI](https://lib.ghostty.org/vt/stability.html)는 안정화됐지만 GPUI 위젯을 제공하지는 않는다. [설치 문서](https://lib.ghostty.org/vt/installing.html)에 플랫폼별 배포 경로가 다르므로 라이브러리와 GPUI 버전을 고정하고 실제 패키지에서 확인해야 한다. Herdr의 벤더링된 GPUI 구성을 DDG가 그대로 써야 하는 것은 아니다. GPU 가속 GUI가 곧 3D 엔진은 아니다. 3D가 필요해지면 독립 WebView 또는 네이티브 렌더러를 별도로 비교한다. 동일 창에 [Wry를 임베드](https://docs.rs/wry/latest/wry/struct.WebViewBuilder.html)하는 경우 Linux Wayland는 별도 검증 대상이다.

## 작업 후보와 통과 기준 (미확정)

| 순서 | 영역 | 할 일과 확인 |
|---|---|---|
| 1 | 빌드 조사 | GPUI 버전과 Ghostty 공식 C ABI 연결 방식, 라이선스·번들 확인. macOS arm64에서 깨끗한 환경으로 창을 띄울 수 있는지 확인. |
| 2 | PTY·VT | 기존 portable-pty 동작을 재사용하고 Tauri IPC 의존만 분리. 한 셸의 순서 있는 출력·입력·VT 응답·resize·종료를 연결. 분할된 UTF-8/VT 스트림에서도 같은 결과이고 UI가 블로킹되지 않아야 함. |
| 3 | 렌더링·입력 | GPUI로 셀·배경·커서·선택·스크롤백을 그리고, Ghostty 키 인코더에 모드와 수정키 전달. 같은 Pi 버전에서 Enter는 제출, Shift+Enter는 줄바꿈; 한글 IME 조합이 커서에 표시되고 한 번만 입력. Powerlevel10k 사선·넓은 문자·높은 DPI·대체 화면 비교. |
| 4 | 교체 후보 | 1–3 통과 후 사이드바·독립 탭·재시작·키보드 접근성 이전. 탭 전환/종료에서 세션 혼선이 없고, 창을 닫으면 셸이 정리되며, 합의한 OS에서 깨끗한 설치가 되어야 함. 통과 전 Tauri 유지. |

## 초기 필수 검증과 데이터 정책 제안

- 별도 DB/네트워크/로그 저장 없음. 탭마다 PTY와 VT 상태를 메모리에 한 번만 소유. 종료된 실행의 이벤트가 새 실행으로 넘어가지 않아야 한다. UI와 무관하게 순서를 보장하고 큐는 제한하되 출력을 조용히 유실시키지 않는다.
- 프로세스 출력은 VT 데이터이지 앱 명령이나 워크플로우 완료 신호가 아니다. FFI 입출력과 세션 ID/그리드 크기는 경계에서 검사하고, 내부에서 중복 검사하지 않는다. OSC의 클립보드 등 호스트 부작용은 별도 허용 전 비활성. 종료·오류는 UI에 표시한다.
- 유닛 테스트 후보: 키 모드별 바이트, 분할 입력, 종료/재시작 시 세션 격리. 실제 앱 수동 확인: Pi·한글 IME·복붙·선택·리사이즈·종료. 자동화 E2E 스위트는 제외.

## 확정 범위와 전환 게이트

- 사용자가 현행 DDG 앱 전체를 GPUI로 전환하는 계획을 요청했다. GPUI를 유일한 앱 경로로 삼고 사이드바·탭·터미널·입력과 상태 UI를 옮긴다. Ghostty 네이티브 VT와 portable-pty를 사용하며, Tauri/WebView/Vite/ghostty-web은 검증 통과 후 제거 대상으로 관리한다. 기존 앱은 전환 전까지 비교·복구 기준으로 보존한다.
- 첫 전환의 동등성 범위는 현행 로컬 데스크톱 앱을 기준으로 한다. 창 종료 시 로컬 셸 종료를 유지한다. 개발용 리로드 재생과 실행 중인 셸은 이관하지 않는다. 기존 제품의 3D·창 독립 실행·원격 목표는 유지하되 이번 전환에 새로 구현하지 않는 것을 권고한다.
- 전환 전 목표 환경에서 깨끗한 빌드·실행, 탭 간 세션 격리, Pi 입력·한글 IME, 렌더링·리사이즈·선택, 종료 정리를 확인한다. 작업 저장과 기존 셸 정상 종료를 안내하고, 이전 소스·빌드로 되돌릴 수 있는 기준점을 확보한다. 롤백은 살아 있던 셸 복원이 아니다. 레거시 삭제·머지는 별도 실행 단계이며 수행하지 않았다.

## 실행 경로 전환 결과

사용자 요청에 따라 기존 앱 프로세스를 종료하고 Tauri/WebView/Vite/ghostty-web 코드·설정·생성물 및 이 작업의 외부 복구 스냅샷을 삭제했다. GPUI만 실행 경로로 남겼다. 이는 기능 동등성이나 G5 통과를 의미하지 않는다. 이전 앱으로의 롤백은 더 이상 제공하지 않으며 남은 검증은 네이티브 앱에서 진행한다. 아래와 위에 기록된 전환 기준은 당시 계획이다.

## 첫 전환 기준

직전 권고에 대한 진행 요청을 반영하여 macOS arm64 개발 환경의 빌드·실행을 기준으로 한다. Windows·Linux 및 설치 패키지는 후속 검증으로 남긴다. 별도 실험을 완료로 보거나 여러 OS와 설치 패키지를 전환의 선행 조건으로 올리지 않는다.
