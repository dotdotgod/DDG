# 화면과 입력 계약

~~~text
닫기 전:   [1] [2] [3*] [+] [×]
2 제거 후: [1] [2*]     [+] [×]
* = 같은 활성 세션 (표시 번호만 변경)
~~~

| 동작 | macOS | Windows / Linux |
|---|---|---|
| 새 탭 | Cmd+T | Ctrl+T |
| 현재 탭 닫기 | Cmd+W | Ctrl+W |
| 왼쪽 | Cmd+Shift+[ | Ctrl+Shift+[ |
| 오른쪽 | Cmd+Shift+] | Ctrl+Shift+] |
| 1–9번째 탭으로 이동 | Cmd+1–9 | Ctrl+1–9 |
| 마지막 탭으로 이동 | Cmd+0 | Ctrl+0 |
| 기존 이동 별칭 | Ctrl+Shift+Tab / Ctrl+Tab | Ctrl+Shift+Tab / Ctrl+Tab |

- 양끝에서 순환한다. 0/1개 이동은 선택 변경 없음. 추가 시 새 탭 포커스, 최대 16개 유지. 마지막 탭을 닫아도 창은 열린 채 비워 두며 다시 열 수 있다.
- 숫자 단축키는 왼쪽부터 현재 표시 순서를 기준으로 한다. 1–9는 해당 위치, 0은 탭이 10개 이상이어도 항상 가장 오른쪽 탭을 선택한다. 해당 위치가 없거나 탭이 없으면 동작하지 않고 키는 소비한다. 선택에 성공하면 터미널에 포커스를 둔다. 수정키 없는 숫자는 기존 터미널 입력으로 전달한다.
- 화면 번호는 Vec의 현재 위치 + 1. 내부 Tab.id와 PTY·VT는 그대로 유지한다. 클릭은 캡처한 ID를 현재 Vec에서 찾고, 사라진 ID는 무시한다. 실행 중인 탭은 기존 비동기 종료 요청 후 Exit에서 제거된다. 요청 오류 시 유지하고, 제거 시 기존 선택 보정으로 살아 있는 활성 세션을 보존한다. 활성 프로세스 종료에는 기존과 같이 별도 확인창을 추가하지 않는다.
- 기존 창 단위 입력 경로를 재사용해 정확한 키·수정키만 판별한다. 이동 별칭은 같은 순환 경로를 쓴다. 일치하면 0개/한도/종료 중에도 소비하고 VT로 보내지 않는다. 일반 입력·붙여넣기는 기존 경로. Windows/Linux의 예약 Ctrl+W/T는 셸의 단어 삭제/문자 전치보다 우선하며 README에 명시한다.
- 키 입력은 GPUI 이벤트 경계에서 해석한다. 내부 ID·선택 인덱스와 기존 typed PTY 이벤트 계약을 유지한다. DB, 외부 응답, 저장·복구, 새 프로세스 I/O 없음. 소규모 변경이므로 별도 키맵 엔진이나 탭 ID 인덱스를 추가하지 않는다.
