# 보관 계획 · 룸 전환 단축키

**2026-11-28 · T0–T1 및 T2-A 실행 완료. T2-B `Unverified`. `main` 통합·원격 push 미승인.** 아래 계약과 실행 순서는 계획 당시 기록이다. 사용자가 원하는 것은 세션을 옮기는 명령이 아니라, 키보드로 다른 룸을 **보는** 동작이다.

## 6하원칙과 결정 기록

| 항목 | 확정 계약 |
|---|---|
| 왜 / 누가 | 여러 머신을 쓰는 DDG 네이티브 사용자(읽기 전용 관찰자 포함)가 사이드바를 클릭하지 않고 룸을 바꾼다. |
| 무엇을 · A1 | 활성 화면만 전환. 대상 룸의 기존 탭 그룹·분할 포커스·패널 확대를 유지한다. 세션 소속·수명·카탈로그·목록 순서는 바꾸지 않는다. |
| 어디서 · A2 | 머신 설정 순서 → 머신 내부 룸 순서로 적격 룸을 이어서 양방향 순환한다. 마지막 다음은 처음, 처음 이전은 마지막이다. |
| 어떻게 · A3 | macOS `⌘+Option+[` / `]`, Windows·Linux `Ctrl+Alt+[` / `]`로 이전/다음. 접힘은 필터가 아니다. 실제 전환 때 `Rooms` 섹션과 대상 머신만 펼친다. |
| 언제 · A4 | 활성 창, 루트 포커스, 일반 Terminal 존에서만. Readonly도 허용. AgentList·Peek·모달·폼·런처·유효한 paste 확인·IME 조합은 기존 소유자에게 맡긴다. 분할 경계 드래그 중에는 소비하되 전환하지 않는다. |
| 어느 머신 · A5 | 사용자 Round 2: 연결 끊김·재연결 머신의 캐시는 건너뛴다. 설계 `DN-1`: 연결됐어도 이번 연결의 카탈로그를 받기 전까지는 목적지에서 제외한다. 출발지에는 연결/제어권을 요구하지 않는다. |

**우선순위:** ① 입력·권한 격리 ② 올바른 목적지·양방향 순환 ③ 자동 펼침·포커스 보존 ④ 기존 키 회귀·사용자 안내. 탭 이동은 `Primary+Shift+대괄호`, 패널 이동은 `Primary+Alt+방향키`, CLI detach는 `Ctrl+]` 그대로다. 비Mac에서는 허용 문맥의 정확한 두 조합만 PTY보다 앱이 우선한다. 다음/보류: 비US 배치나 WM 선점 문제가 관측되면 대체 바인딩을 별도 검토. 키 편집기·전역 훅·자동 스크롤·룸 재정렬·서버 변경은 범위 밖이다.

## 역할·리뷰와 실행 순서

Astra가 요구사항·필수 검증·실행 인계를 담당한다. Neon이 설계와 기술 리뷰를 소유한다. 별도 Neon 리뷰 2건 결과는 C–D 네 역할 **통과**, E 최초 12건 반영 및 `F-R1` 정정 후 **진행 가능**이다. 이는 설계 리뷰이지 제품 테스트 통과가 아니다.

| 순서 | 담당·영역 | 선행 조건 → 독립 완료 기준 |
|---|---|---|
| T0 조사 | Astra / 실행 환경 | 실행 착수 지시 → Sol 인증, Ghostty, 삽입 앵커·기존 변경 기준선 확인 |
| T1 구현·TDD | Sol medium / native UI·가이드; Neon 독립 검수 | T0 통과 → 기능과 UT 동시 구현, native/workspace 테스트 출력, diff 검수 통과 |
| T2-A ∥ T2-B 검증 | 사람 / macOS H1 ∥ Windows/Linux H2 | 동일한 T1 검수본 → 서로 다른 환경·데몬·호스트로 검증. H1 실측 필요; H2 미가용 환경은 이유를 적어 `Unverified` |
| T3 종료 | Astra / 보고·인덱스·통합 | 검증 결과 수집 → `FINAL.md`와 완료 계획 상호 연결. `main` 머지·push는 각각 사용자 명시 승인·권한 확인 후에만 |

구현 변경 지점이 `native/src/main.rs`에 모여 있어 구현을 병렬 분할하지 않는다. 실기만 격리된 동일 리비전으로 병렬화한다. 기한·사람 검증자·가용 비Mac 장비는 미정이다. 미결정 제품 요구는 없다. 테스트 실패·환경 부재는 해당 태스크 상태로 기록하고 계획 완료와 구분한다.
