# 터미널 렌더링 최적화 — 플래닝 보고

[활성 계획](../../../../plan/terminal-render-performance/README.md) · [보고 목차](README.md)

- 범위: 계획 작성. 기존 GPUI 화면과 PTY 유지, 폰트/스타일 구간 우선, 행 재사용은 측정에 따른 조건부. 구현·벤치마크·머지 없음. 비가역 작업 없음.
- 초기 기준: 독립 Pi 병렬 사용자(t333), 검증(t334), 데이터(t335) 결과 수집. 화면 외형과 기능의 변경이 없으므로 별도 UX 변경 설계는 제외하고 기존 화면의 ASCII와 동등성 계약을 기록했다.
- 독립 검토: 테스트(t33g), 보안(t33h), 데이터(t33j), 화면(t33k) 수집. 모두 요청 모델 없음, 실제 litellm / cli-proxy/gpt-6.2-sol, 읽기 전용·재위임 없음. 설계·태스크 통합은 주 세션에서 수행했다.
- 반영: 같은 색만으로 조판 안전을 가정하지 않음, 커서와 화면 단일 갱신, 캐시의 VT 격리, 합성 데이터만 계측, 변경 전후의 동일 release 재생 및 실제 Pi 확인. 반영본 독립 재검토는 미수행.
- 착수점: P0 기준선, P1–P2 최소 변경, P3 측정 기반 선택, P4 검증. 실제 병목과 Ghostty의 dirty/clear 규약은 미검증이다. 전용 GPU 렌더러 전체 이식은 선행 측정 없이 과도하고, 폰트 캐시만으로는 셀 요소 비용을 없앨 수 없어 둘을 구분해 측정한다.
