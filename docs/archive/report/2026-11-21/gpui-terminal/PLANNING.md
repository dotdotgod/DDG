## 후속 결정: GPUI 전면 전환

- 사용자가 별도 실험이 아니라 현행 앱 전체를 GPUI로 교체하는 계획을 요청했다. 기술 방향은 확정이며, 첫 전환의 OS/아키텍처와 설치형 배포 필요 여부는 확인 중이다.
- 사용자 요구(t2n8), 데이터(t2n9), 검증 필수사항(t2nb)은 독립 Pi 세션에서 병렬 재검토했다. 요청 모델 없음, 실제 `litellm / cli-proxy/gpt-6.2-sol`, 읽기 전용 조사, 재위임 없음. 세 결과 모두 수집했으며 공통 게이트는 활성 계획에 통합했다.
- 상태: 부분 완료. UX·레이어 설계와 리뷰·실행 태스크는 지원 및 배포 조건 확정 이후 진행한다. 구현·빌드·전환·삭제·머지는 하지 않았다.

## 실행 인계 준비: macOS arm64 개발 실행

- 앞선 권고에 대한 진행 요청으로 macOS arm64 개발 실행을 첫 전환 기준으로 적용했다. Windows·Linux·설치 패키지·3D·재접속은 후속이다. 전면 교체의 방향은 유지하되, Tauri는 검증과 롤백의 기준으로 남긴다.
- [설계](../../../plan/gpui-terminal/DESIGN.md)와 [실행 태스크](../../../plan/gpui-terminal/TASKS.md)를 작성했다. G1 빌드·기준점 조사 → G2 실행/G3 터미널 → G4 앱 통합 → G5 실기 검증·롤백 → G6 전환 순서다.
- 독립 Pi 역할 결과: UX 설계(t2nc), UX 리뷰(t2nf), UX 보안(t2nd), Presentation 설계(t2ng), 실행·데이터 설계(t2nh), Presentation 리뷰(t2nm), 데이터 리뷰(t2nn), 보안 리뷰(t2nj), 테스트 설계 및 자체 리뷰(t2nk, 독립 테스트 리뷰 아님). 모두 동일 환경 기본 모델 `litellm / cli-proxy/gpt-6.2-sol`, 읽기 전용, 재위임 없음.
- 통합 검토: 탭 제거는 해당 실행 회수 확인 후에만, 포화 큐와 독립된 취소 경로, 비동기 종료의 포커스 보호, OSC 클립보드 읽기·쓰기 차단, 실제 VoiceOver·IME 및 롤백 검증을 설계와 태스크에 연결했다. 수정본에 대한 독립 재검토는 미수행이다.
- 상태: 실행 인계 문서 작성 완료, 독립 재검토와 구현·실기 검증 미완료. 네이티브 버전·빌드 명령과 복구 기준점은 G1에서 확정한다. 구현 세션은 자동 시작하지 않았다. 기존 경로 삭제·전환은 실기 검증과 해당 승인 전 금지, 머지는 범위 밖이다.
