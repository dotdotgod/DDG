# GPUI 터미널 렌더링 최적화

상태: **부분 완료 · 보류** — `P1`(창 초기화 시 폰트 그리드 캐시)과 `P2`(`vt::frame()` 통합 스냅샷·동일 색상 ASCII 구간 묶음)는 구현 완료. `P0`/`P3`/`P4`(release 기준선 측정, 변경 행 캐시, 실기 성능 비교)는 호스트 세션(H0) 및 렌더러 방향 확정 전까지 보류한다.

[검토 보고](../../archive/report/2026-11-21/terminal-render-performance/PLANNING.md) · [제품 요구사항](../../spec/requirements.md)

## 범위와 근거
macOS arm64의 기존 DDG 터미널에서 출력 중 입력·스크롤 지연을 줄인다. 레이아웃, 색과 글꼴 선택, PTY 동작을 유지한다. 이전 앱 복구, 새 폰트 설정, IME 개선, 범용 렌더러 교체는 제외한다. [GPUI 화면](../../../native/src/main.rs)은 매 render마다 폰트를 열거하고 셀마다 요소를 만든다. [VT](../../../crates/ddg-agents-vt/src/terminal.rs)는 화면과 커서를 따로 갱신한다. 이는 코드에서 확인한 비용 후보이며 실측 병목은 아니다. [Herdr](https://github.com/herdrdev/herdr-app/blob/b41b5cbf/src/terminal.rs)의 스타일 구간과 행 재사용을 참고하되 전용 렌더러를 통째로 이식하지 않는다.

## 화면·데이터 계약

```text
+----------+-----------------------+
| Ddg      | [Terminal 1] [+] [x] |
| 상태     | 기존 셀·색·커서 그리드 |
+----------+-----------------------+
```

- 폰트 해석과 측정은 창 수명에 귀속한다. MesloLGS NF → Menlo 순서를 보존하고, 실제 폰트 입력 변경 때만 무효화한다. 현재 폰트 변경 감시 기능을 새로 만들지 않는다. PTY 크기와 커서는 같은 셀 메트릭을 쓴다.
- 인접 셀의 전경·배경이 같고 기존 셀 폭·클리핑·조판이 보존되는 구간만 합친다. 단순 고정폭부터 시작한다. 넓은 글자, 결합 문자, 대체 글리프 등 안전하지 않은 경우 기존 셀 경로 유지. 빈 셀 배경도 보존한다. VT 화면과 커서는 한 번의 render-state update에서 읽는다.
- 행 재사용은 조건부다. 동일 VT 실행의 메모리 안에서만 캐시한다. Ghostty 1.0.1의 dirty/clear·행 식별 규약을 헤더와 테스트로 확인한 뒤 사용하고, 스크롤/리사이즈/재흐름/대체 화면/팔레트/재시작 등 동일성 불명 시 전체 갱신한다. 탭 사이 화면 데이터 공유 없음.
- DB·외부 응답·영속 저장 없음. PTY 바이트는 기존 FFI 경계에서 파싱하고 내부 렌더 모델을 재검증하지 않는다. 기존 PTY 순서·응답과 OSC 차단 유지. 측정에는 합성 출력과 집계치만 남긴다.

## 실행 태스크

구현 세션은 `/Users/dotdot/.agents/skills/ddg-planning/roles/implementer.md`를 읽는다. 아래 항목을 순서대로 수행한다. P1/P2는 같은 화면 소스를 바꾸므로 순차 적용한다.

| ID | 유형·영역 | 산출물·통과 기준 |
|---|---|---|
| P0 | 조사 · 성능 | 현재 소스에서 release 기준선을 만든다. 동일 기기·창/그리드·폰트·배율에서 워밍업 후 합성 PTY 출력(같은 색 긴 구간, 교대색, 한 줄 갱신)을 반복한다. p95 렌더 시간, 생성 요소 수, VT 추출·화면 구성/그리기 비용을 기록한다. 기존 사용자 세션을 녹화하거나 종료하지 않는다. |
| P1 | 구현 · 폰트 | main.rs에서 설치 폰트 열거와 메트릭 측정을 warm render 경로에서 제거한다. 두 폰트에서 기존 그리드·커서 위치와 `stty size`의 일치를 확인한다. 단순 초기화에 전용 mock 없음. |
| P2 | 구현 · 화면/VT | main.rs/vt.rs에 안전한 스타일 구간과 공통 화면·커서 스냅샷을 적용한다. 유닛 TDD: 고정폭 범위, 색 경계, 색 있는 빈칸과 넓은/결합 문자에서 기대 열과 스타일을 확인. 기존 VT/PTY 테스트 및 OSC 응답 계약 유지. P0 재실행으로 요소 수 감소와 반복 측정 변동보다 큰 p95 개선, 교대색 회귀 없음 확인. |
| P3 | 조건부 조사·구현 · 행 | P2 이후에도 VT 추출·행 준비 비용이 병목일 때만 dirty 규약 검증 후 구현. 한 줄 수정은 해당 행만 재생성, 커서만 변경하면 행 재생성 없음. 탭 전환·재시작·스크롤·resize·palette·alt screen은 전체 갱신 결과와 일치해야 한다. 비용 또는 규약이 확인되지 않으면 보류 사유를 기록하고 전체 갱신 유지. |
| P4 | 검증 · 네이티브 앱 | 기존 macOS release 기준과 비교하고 실제 Pi 입력·붙여넣기·스크롤·리사이즈의 반응 및 색/커서·Retina·글리프 위치를 확인한다. 실제 앱 결과와 유닛 결과를 분리한다. 새 자동화 E2E 없음. |

측정으로 사용자 체감 지연이 남으면 원인을 기록한다. 근거 없이 FPS 목표나 별도 캐시 계층을 추가하지 않는다. 삭제·배포·머지는 범위 밖이다.
